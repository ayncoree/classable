# ClassAble Ideathon MVP — Outcomes

## [ ] 1. Real microphone-to-text and live captions
- Click Start Captions, grant microphone permission, speak a sentence, and display actual browser-recognized words—not a recording-only or fabricated result. Use `SpeechRecognition` or `webkitSpeechRecognition` where available; display interim text distinctly, append actual final results without duplicate segments, and support English/Hindi where the engine supports them.
- Provide working Start, Pause, Resume and Stop controls; show microphone/recognition states; clear active capture on stop/session end/unmount; show honest unsupported-browser, denied-permission, network-error and interrupted-recognition messages. Log the actual SpeechRecognition error code and distinguish `network`, `not-allowed`, `service-not-allowed`, `no-speech`, unsupported browser and other errors. Stop fatal browser-service instances rather than looping restarts; Resume creates a fresh instance.
- Keep captions readable and distraction-free with auto-scroll and an opt-out, font size, high contrast, light/dark caption surfaces, language selector, elapsed time, confirmed transcript clearing, save/download actions and persistent browser-demo transcript data.
- If no supported browser engine is available, clearly state that fact; keep any configured server transcription API as a genuine alternative only. Do not treat permission success or recorded audio as a successful transcription.

## [ ] 2. Teacher/student demo and shared caption channel
- Teacher can select/create a demo class, start a live lecture, speak and see actual interim/final captions, then pause/resume/end. Student can open the matching demo class/session, read large accessible captions without enabling a microphone, and see new finalized captions as they arrive.
- Use the existing same-origin local demo state/`BroadcastChannel` for synchronization between ClassAble tabs in one browser. Clearly label that it is a local demo and does not guarantee independent-device sync. Where authenticated cross-device sessions are used, keep server authorization and existing short MySQL session polling; do not add custom SSE/reconnection machinery.
- Show meaningful session state and errors; do not show captions as live after recognition stops or a connection fails. Keep role selection as demo navigation only, never as an authenticated permission check.

## [ ] 3. Audio import, transcript persistence and privacy
- Let a user choose supported lecture audio (WAV, MP3, WebM, Ogg, MP4 or M4A where accepted), show filename and processing state, and submit actual audio only to the server transcription provider (maximum 10 MB). This audio-only endpoint is usable without demo sign-in, stores no class data, and applies six requests per authenticated account/source IP per 15 minutes and two concurrent requests per caller using process-local counters (not global across multiple server instances). Display actual returned text/segments or an explicit error and allow review/edit/save. Never say a file was transcribed merely because it was selected or uploaded.
- Keep the 20-second `MediaRecorder` fallback where the browser speech service is unavailable or errors; show processing state, release microphone tracks, return only real service text and preserve useful recording/API error messages. Do not label batch fallback transcription as streaming. Provider credentials stay server-side; if missing, show the named setup requirement instead of pretending it works.
- Browser live captions and completed demo sessions remain saved and viewable as transcripts. Teachers can review/edit a transcript and publish/unpublish it; saved output preserves actual original words when available. Uploaded audio itself is not retained by ClassAble.
- For authenticated classes, enforce server-side teacher/class-membership permissions. Students may receive an authorized live class stream but must not see ended/unpublished transcript/caption data or teacher-only private transcript notes. The role-picker demo storage is not a security boundary.

## [x] 4. Transcript-based notes and summaries
- From real transcript text, offer a clearly labeled extractive summary using transcript sentences; do not call it AI-generated or invent facts. Let the user edit and save the summary.
- Provide editable manual lecture notes, save/reopen behavior, copy a selected transcript passage into notes, and TXT/Markdown export. Keep student-authored notes distinct from teacher-private notes. These features work without an AI service.

## [ ] 5. Simple class workspaces and optional resources
- Keep clear Teacher and Student demo interfaces: teacher My Classes, select/create class, Live Classroom, saved transcripts and lecture notes; student My Classes, open/join a demo class, Live Lecture, captions, saved transcripts and notes. Use sample/demo data where needed; do not build complex administration, assignments or analytics into the core flow.
- Keep the existing resource/materials module optional. Include sign-language video resources only when a source is actually verified; otherwise show no fabricated/“verified” links. Do not imply the caption interface performs automatic ISL translation or camera-based sign recognition.

## [ ] 6. Preserve design and validate the MVP
- Preserve ClassAble branding and the existing warm-ivory/forest/sage design, accessible layout and 3D/GSAP landing hero. Keep keyboard-readable controls, reduced-motion behavior and no student microphone requirement.
- Run the app, TypeScript check, production build and available tests. Exercise actual microphone-to-text and teacher-to-student behavior where the browser/device permits; verify transcript save and real transcript-derived notes. If the runtime cannot supply a microphone, independent authenticated accounts or a service response, state exactly which parts were source-verified versus exercised.

## ClassAble lecture-materials and hero upgrade

### [x] Reusable transcript templates and reading workspace
- Include Standard Lecture (lecture title, course, instructor, date, timestamps, transcript and key takeaways); Detailed Lecture (timestamped sections, speaker labels when available, definitions, examples and important explanations); Revision Transcript (concise transcript highlights, key concepts, important terminology and exam-relevant points); Accessible Transcript (readable paragraphs, clear speaker labels when available, keyboard-friendly controls, adjustable text size and high contrast); and Meeting / Discussion (speaker-separated dialogue when supported, decisions, questions and action items).
- Search transcripts by title, course, date and content; edit transcript text and rename documents; create, duplicate, rename and delete templates; export transcripts as TXT and Markdown and offer PDF export if supported.
- Keep original transcript text separate from generated summaries and edited notes. Never invent timestamps or speaker identities when the source does not provide them.

### [x] Lecture notes and study-material templates
- Provide Structured Study Notes (lecture title and learning objectives; main headings and subheadings; definitions and explanations; examples; key takeaways; unclear or unanswered questions), Exam Revision Notes (important concepts; essential facts and terminology; formulas where relevant; common mistakes; short-answer revision questions), Cornell Notes (cue/question column, detailed notes column, summary section), Flashcards (question front, answer back, editable cards and simple review mode), Lecture Summary (short overview, main ideas, supporting details, conclusions and next steps), and Practice Questions (multiple-choice and short-answer questions, answer key with explanations, difficulty labels).
- Let students create notes from a saved transcript, edit them, save versions and export them. All generated materials must be based on actual transcript text; if a transcript is missing or too short, explain that instead of generating fabricated lecture content.

### [x] End-to-end lecture document flow
- Connect record/import audio → transcribe actual audio → save transcript → choose a transcript template → generate lecture notes → create revision questions or flashcards → edit and export. Keep existing teacher/student portals and real speech-to-text integration working. If external transcription is unconfigured, explain what is missing instead of showing fake results.
- Give each lecture a dedicated page with Transcript, Notes, Summary, Flashcards and Questions tabs. Add a Generate Study Materials action with selectable output types and functional loading, success, empty and error states.
- Test creating, editing, saving, searching and exporting documents; test the lecture material flow using saved transcript text.

### [x] Premium accessible 3D landing hero
- Substantially refine the existing 3D hero into a premium, cinematic, accessibility-focused centerpiece: warm ivory, forest green, muted sage and restrained gold; sculptural knowledge/communication forms; layered translucent glass and paper; floating typographic elements; soft light, subtle particles, connected nodes or sound waves; depth, realistic materials, soft shadows, ambient lighting and controlled reflections.
- Coordinate a restrained entrance and scroll motion using existing GSAP; provide slow float/rotation and subtle cursor response without constant distracting motion. Keep all headline, navigation, buttons and accessibility controls as normal HTML.
- Lazy-load and optimize the scene; retain a graceful static fallback when WebGL is unavailable; honor reduced-motion preferences; support mobile and lower-powered devices; preserve working routes and controls.
- Test the 3D hero on desktop and mobile, including the static fallback and reduced-motion behavior.
