# ClassAble MVP: setup and honest boundaries

## Fast classroom demo

Choose **Teacher demo** or **Student demo** without an account. The demo stores classes, sessions, transcript drafts, role-tagged notes and accessibility preferences in this browser. `BroadcastChannel` and the `storage` event share updates between tabs of the same browser origin; they do not connect separate browsers or devices. Demo mode is a presentation boundary, not an account-security boundary.

The initial demo join codes are `BIO101`, `EMATH2` and `CSCI01`. Join the matching class in the student portal, then view **Live Classroom**. The teacher can end a session to save recognized final text as a draft transcript, correct it, and publish/unpublish it for the student demo. Same-origin tab synchronization is intended through `BroadcastChannel` and the `storage` event; separate browsers/devices do not sync in local demo mode.

## Actual transcription

The first path is the browser's native `SpeechRecognition`/`webkitSpeechRecognition`. It needs a supported browser/OS and microphone permission; only actual returned recognition results become live captions. A browser speech service may return `network` even when microphone permission is granted or general internet access works. ClassAble logs the actual error code, shows a specific message, stops a fatal browser-recognition instance rather than rapidly restarting it, and leaves the server fallback available. Diagnostics distinguish `network`, `not-allowed`, `service-not-allowed`, `no-speech`, unsupported browser and other codes. Resume starts a fresh recognition instance. English and Hindi are selectable where that browser speech service supports them.

The short `MediaRecorder` fallback and audio-file import submit real audio through the server-only speech provider. Provider credentials (`MANUS_API_URL` and `MANUS_API_KEY`) are read only on the server. Audio-only transcription is available without an account for the local demo; it accepts WAV, MP3, WebM, Ogg, MP4 or M4A, up to 10 MB. The server applies six requests per 15 minutes and two concurrent requests per authenticated account or source IP, using process-local in-memory counters; these are not global limits across multiple server instances. This endpoint receives no class data, and ClassAble does not persist uploaded audio. Actual returned words appear as final captions in a live session; ending the session creates its transcript draft. Short microphone recordings stop after 20 seconds or when the teacher stops them; they are batch transcription, not streaming. If the server credentials are absent or the service fails, the interface reports that instead of fabricating text.

## Persisted cross-device classroom

The signed-in workspace uses Manus OAuth, the managed server and MySQL. In `/connected/teacher` or `/connected/student`, sign in with the corresponding teacher/student account, create or join a class, and run a live session. Membership and teacher actions are enforced on the server. Students receive authorized session state by polling MySQL about every 2.5 seconds (transcripts every 3 seconds); there is no custom SSE or external real-time service. This is a simple cross-device path, not sub-second push, and has not been exercised end-to-end with two independent signed-in devices in this sandbox.

Connected transcript listing restricts drafts to class owners, hides teacher-only private notes from students, and permits transcript edits/publish controls only to the class teacher. Student notes are scoped to the signed-in account. In the local demo, ended transcripts are hidden from students until published and notes are separated by role, but the shared browser storage is not secure against someone who can access that browser.

If a connected teacher closes a tab unexpectedly, an unended session may remain shown as live until the teacher returns and pauses or ends it. Explicit pause/end waits for returned browser finals and caption writes; if they cannot be confirmed, the session remains paused and no transcript is finalized. The core session/caption/transcript persistence uses the existing managed schema; no new migrations are required for this speech fix.

## Notes and optional materials

The **Transcript Library** can generate a basic extractive summary from actual transcript sentences, then let the user edit/save it and copy passages into notes. It is not an AI summary service. Assignment authoring, analytics and language translation/ISL recognition are deferred from the ideathon MVP. Existing **Learning/Lecture Materials** can host optional reference links; no verified sign-language video links were present in the supplied project materials, so no unverified links are represented as vetted resources.

Lecture documents include Transcript, Notes, Summary, Flashcards and Questions tabs, reusable transcript/study templates, editing, TXT/Markdown export, and saved material versions. Study notes, summaries, flashcards and question drafts are derived from saved transcript text and are marked as drafts to review; source text remains separate from edited/generated material. Built-in transcript reading layouts have fixed renderers and their section lists are read-only; duplicate one to create an editable custom section outline. Study templates and custom transcript templates remain editable. The local Teacher demo manages these reusable templates. After a teacher publishes a transcript in the demo, the Student Transcript Library can read it and generate role-owned notes, flashcards and questions, which appear in Student My Notes. Student views do not show the teacher-private transcript-note field. Demo roles and localStorage are for presentation, not a security boundary or independent-device sync; the authenticated server remains the security boundary for connected use.

## Validation and how to test

The final checks pass: `pnpm check`, `pnpm build`, and `pnpm test` (20 tests, including distinct browser speech error messages, transcript-derived material tests and template-section editing policy). On 2026-10-22, the real 6.53-second spoken WAV phrase `Classable microphone test. One, two, three. This is a real speech transcription check.` traversed **Teacher Live Classroom → audio import → server transcription API → local saved session → student Live Classroom**. The actual returned text appeared as one finalized teacher caption and then in the joined student view in the same browser, with the student microphone not requested. Saving that caption to student notes succeeded. Ending the session created a transcript; the teacher generated and saved an extractive summary from its actual transcript text. In the document workspace, the teacher created and edited source-grounded notes, summary, flashcards and questions; saved a material version; downloaded a Markdown study-material export; and tested create/edit/save/delete in both the study-template and transcript-template managers, restoring the built-in lists afterward. Built-in transcript section fields are read-only, and a browser check confirmed a duplicated custom template is editable and can be removed. A published transcript was then visible to the Student demo without its teacher-private notes; student-generated materials remained role-owned and appeared in Student My Notes. The same-origin route manifest served HTTP 200 and matched five declared routes. Visual checks covered desktop with reduced motion and a 390px WebGL-disabled static fallback. This was sequential same-browser navigation, not a simultaneous two-tab BroadcastChannel test, and does not prove independent-device sync. The physical microphone was unavailable in the sandbox (`Requested device not found`), so Web Speech and MediaRecorder microphone capture still need a physical-device test. The production build passes with the existing Vite warning about the non-module platform-config script and a large 3D hero chunk.

To test with a microphone: open ClassAble Preview in a supported secure-origin browser; choose **Teacher demo → Live Classroom**; select a class and **Start live session**; grant microphone permission, then speak a full sentence. Interim text appears separately and actual final words increment the finalized count. To test the fallback, wait for a browser-service error (or use a browser without `SpeechRecognition`); the page reports the specific code and offers **Record a short segment**. Record speech and stop (maximum 20 seconds), then wait for the server response. The real returned words should appear in captions; stop/end the lesson to save the transcript. To test a prepared clip, choose a WAV/MP3/WebM/Ogg/MP4/M4A file up to 10 MB in the import panel; wait for actual returned text in the live caption view, end the session, then inspect its saved draft under **Transcripts**. Provider-not-configured and network errors are displayed without fake captions.
